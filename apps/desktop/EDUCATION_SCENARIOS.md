# 萌学伴 · Hermes 教研场景方案

状态：方案评审稿  
更新时间：2026-07-28  
适用范围：萌学伴桌面端，远程 Hermes Gateway（operator + mxb001～mxb004）

实施任务清单：[`EDUCATION_IMPLEMENTATION_PLAN.md`](./EDUCATION_IMPLEMENTATION_PLAN.md)

## 1. 推荐结论

推荐采用 **任务导向首页**，并以 **场景包** 作为主要启动方式：

- 首页回答“今天要完成什么”；
- 任务卡回答“这件事现在做到哪里”；
- 数据来源中心回答“有哪些资料可用”；
- 场景包回答“这类工作如何稳定完成”；
- 助手模板回答“由什么角色和能力组合来做”；
- 产物中心回答“最后生成了什么文件”。

不建议把“选择助手”或“选择数据来源”设为第一步。教师通常先知道目标，
未必知道应该调用哪个 Profile、Skill、模型或来源。

## 2. 与 Hermes 的对应关系

| 业务概念 | 教师看到的内容 | Hermes 实现 |
| --- | --- | --- |
| 助手模板 | 教材结构助手、教研资料助手、备课助手 | Profile 初始配置 + SOUL + 默认模型 + Skills/Toolsets |
| 场景包 | 教材树整理、专题研究、文档整理等 | 输入表单 + 助手模板 + 来源要求 + 执行配方 + 产物约定 |
| 任务卡 | 进度、等待确认、失败步骤、产物 | Session + Goal + 场景快照 + 业务状态 |
| 数据来源 | 学科网、知识库、联网搜索、上传文件 | Skill/工具/连接配置 + 能力与可用状态 |
| 产物 | Excel、Word、PDF、图片、研究报告 | Hermes Artifacts + 任务与场景元数据 |
| 定时任务 | 每周动态、资料更新提醒 | Hermes Cron + 消息投递 + Artifacts |

这里的“助手模板”只在新建任务时确定运行配置，不在执行中的会话里动态切换
SOUL 或工具，避免破坏 Hermes 会话缓存和上下文一致性。

## 3. 三套首页组织方式

### 方案 A：任务导向首页（推荐）

适合大多数教师、教研员和内容运营人员。

```text
┌─────────────────────────────────────────────────────────────────┐
│ 萌学伴                         搜索任务、场景或产物              │
├───────────┬───────────────────────────────────┬─────────────────┤
│ 首页      │ 今天想完成什么？                  │ 继续处理        │
│ 对话      │ [ 描述目标或选择下面的场景…… ]   │ ○ 等待选择教材  │
│ 任务      │                                   │ ◐ 专题资料整理  │
│ 数据来源  │ 常用场景                          │ ✓ 教材树已完成  │
│ 产物      │ 教材课程树  知识点树  文档整理    │                 │
│           │ 专项突破    备课资料  教研动态    │ 来源状态        │
│           │                                   │ 5 可用 / 1 降级 │
│           │ 最近产物                          │                 │
│           │ 五年级数学沪教版教材课程树.xlsx  │                 │
└───────────┴───────────────────────────────────┴─────────────────┘
```

优点：目标清楚、第一次使用成本低，最贴合“明确目的后执行”的要求。  
代价：需要新增首页与业务任务记录，但后台执行能力可复用现有 Hermes。

### 方案 B：角色助手首页

首页先展示“教材结构助手、备课助手、教研研究助手、文档整理助手”，选择助手
后再显示适合它的场景。

适合：机构已经按岗位分工，使用者对“找谁做”比“怎么做”更熟悉。  
问题：同一场景容易被复制到多个助手；新用户仍需理解助手边界。因此建议仅将
助手作为首页筛选维度，不作为默认主入口。

### 方案 C：资料来源首页

首页按“教材平台、内部教材库、互联网、我的文件”组织，并展示每个来源可执行
的动作。

适合：内容运营、数据维护人员，以及排查“某来源能否获得某类数据”。  
问题：普通教师容易把“从哪里找”误当成“我要完成什么”。建议将它落为独立的
数据来源中心，而不是全员默认首页。

## 4. 统一任务创建卡

所有场景使用同一套五步结构，但不同场景只显示必要字段：

```text
1 目标          2 范围          3 资料来源          4 产物          5 确认
整理什么？  →  学段/学科等  →  自动推荐，可调整  →  文件与内容  →  创建任务
```

任务确认页必须用一行自然语言概括：

> 整理“小学五年级 · 数学 · 沪教版 · 上下册”的教材课程树，优先使用学科网，
> 输出一个可阅读且保留导入 ID 的 Excel 工作簿。

如果学科网返回“沪教版、沪教版（五四制）、沪教版（2025）”等多个候选，任务
进入“等待确认”，显示候选差异与来源原文，不自动猜测。

## 5. 首批教研场景包

### 场景 1：教材课程树整理

**适用人群：** 教研员、内容运营  
**完成目标：** 得到指定教材版本上册/下册的“单元—课程”完整树。

必填输入：

- 学段、年级、学科；
- 教材版本（如存在同名多版本，进入确认卡）；
- 学期范围：上册、下册或上下册；
- 期望产物：默认 Excel 工作簿。

推荐来源：学科网或已配置教材来源。教师界面不展示内部来源供应商名称，不同
来源的数据仍必须在任务内部保持独立，不能混写。  
执行能力：来源对应的教材结构 Skill、浏览器读取，必要时由视觉模型理解页面。  
产物：教材课程树 XLSX；目录展开可读，同时保留节点 ID、父节点 ID、完整路径、
来源 URL 等后续导入字段。  
特殊状态：某教材只有上册属于正常结果，任务显示“已完成（该来源未提供下册）”
并在工作簿概览中备注。

### 场景 2：学科知识点树整理

**适用人群：** 学科教研员、题库和内容运营  
**完成目标：** 得到“学段 + 学科”维度的学科知识点树。

必填输入：

- 学段、学科；
- 数据来源；
- 期望层级和产物格式。

年级和教材版本默认不作为知识点树的限制条件；只有来源明确提供相应维度时才
显示为可选过滤项。  
产物：学科知识点树 XLSX，目录树、层级列、完整路径与来源 ID 同处一个主工作
表，保证人读和系统导入都可用。

### 场景 3：专项突破目录整理

**适用人群：** 学科教师、专题教研组  
**完成目标：** 获取学科网页面“专项突破”树，例如作文、阅读、课文朗读等。

必填输入：

- 学段、学科；
- 专项目录范围；
- 是否需要关联当前教材范围（默认否）。

产物：专项突破树 XLSX。专项树与教材课程树、学科知识点树分别输出，不依据
名称擅自建立映射。若来源以后明确提供关联 ID，可新增“来源映射”工作表。

### 场景 4：PDF / Word / 图片批量整理

**适用人群：** 全体教师、内容运营  
**完成目标：** 将多份教研资料整理成摘要、目录、对比表或结构化 Excel。

必填输入：

- 上传文件或远程文件；
- 整理目的（摘要、目录、抽取字段、跨文件对比等）；
- 输出格式。

处理策略：

- 图片与扫描 PDF：页面转图后交给默认视觉 API 模型理解；
- 文本 PDF 与 Word：先保留原始文本、标题、表格等结构，再交给 API 模型理解；
- 不把本地 OCR 当成必需依赖，也不向用户展示“OCR 模式”选择。

产物：结构化 XLSX、Word 摘要或 Markdown 报告；每条内容可回到源文件和页码。

### 场景 5：多来源专题教研

**适用人群：** 教研组长、课题研究人员  
**完成目标：** 围绕一个明确主题汇总内部教材、平台目录、互联网资料和用户文件。

必填输入：

- 研究问题，必须是完整目的而非一个孤立关键词；
- 学段、学科及时间范围；
- 允许使用的数据来源；
- 产物类型：资料清单、证据摘要、专题报告或教学建议。

推荐来源：知识库、SearXNG 联网搜索、学科网目录、上传文件。  
执行方式：资料发现可并行；合并报告等待各来源返回或达到超时边界。  
产物：来源清单 + 证据摘要 + 研究报告。网页搜索结果保留标题、URL、发布日期和
访问时间，不能将摘要当成教材原文。

### 场景 6：备课资料包生成

**适用人群：** 一线教师  
**完成目标：** 围绕已确认课程，形成一套可编辑的备课资料。

必填输入：

- 教材版本、年级、册次、单元和课程；
- 课时数、教学目标或教师补充要求；
- 允许引用的教材/知识/文件来源；
- 需要的产物：教案、讲义、课堂活动、练习建议等。

前置条件：先确认真实教材目录和所选课程；知识点只在来源提供明确对应关系时
自动带入，否则让教师选择，不按名称猜测。  
产物：一个任务下的多个可编辑文件，并在产物中心以“备课资料包”分组展示。

### 场景 7：教研动态定期追踪

**适用人群：** 教研管理者、学科组长  
**完成目标：** 定期追踪政策、课程标准、公开教研活动或指定主题的新资料。

必填输入：

- 监测主题和目标；
- 官方站点/搜索来源；
- 频率与投递渠道；
- 变化阈值：所有新增、重点变化或仅指定类型。

执行能力：SearXNG、网页读取、Hermes Cron、消息投递。  
产物：每期简报和新增资料清单；无有效新增时显示“本期无新增”，不生成空报告。

## 6. 数据来源中心

数据来源不只是“有没有配置密钥”，每一行应回答四件事：

| 来源 | 能做什么 | 支持范围 | 当前状态 |
| --- | --- | --- | --- |
| 学科网 | 教材目录、学科知识点、专项突破 | 按站点实时返回 | 可用 / 降级 / 需登录 |
| 知识库 | 内部教材与教研资料检索、读取 | 已收录资料范围 | 可用 / 数据不完整 |
| SearXNG | 联网发现公开网页 | 通用互联网 | 可用 / 限流 / 无结果 |
| 网页地址 | 读取指定 URL | 单页或站点允许范围 | 可用 / 页面不可读 |
| 文件 | PDF、Word、图片等 | 用户上传或远程可见文件 | 可用 / 文件不可达 |

来源详情建议展示：能力、适用场景、支持范围、上次成功时间、一次“测试读取”结果。
账号、地址、模型、实例等技术配置放在“高级设置”。

## 7. 助手模板

首批只需要四个，不要让助手数量等于场景数量：

| 助手模板 | 适合任务 | 默认能力 |
| --- | --- | --- |
| 教材结构助手 | 课程树、知识点树、专项树 | 教材来源 Skills、网页读取、Excel 导出 |
| 教研资料助手 | 专题研究、政策与资料汇总 | 知识库、联网搜索、网页读取、文档处理 |
| 文档整理助手 | PDF/Word/图片批处理 | 文件读取、视觉 API、结构化导出 |
| 备课助手 | 教案、讲义、课堂活动 | 已确认教材上下文、文档生成、产物打包 |

助手卡显示角色、适合完成什么、能访问哪些来源；默认模型和 Profile 名称仅在
技术详情中展示。

## 8. 任务中心

任务列表默认按“需要我处理、进行中、已完成”分组，而不是只按时间排列。

```text
需要我处理
  请选择教材版本     小学五年级数学教材树     [去确认]

进行中
  正在读取第 2 个来源  多来源专题教研          [查看进度]

已完成
  已生成 2 个文件      沪教版教材课程树        [打开产物]
  部分完成：缺少下册   一年级数学教材树        [查看说明]
```

任务详情按业务步骤显示，不暴露每一个模型 Tool Call：

1. 已确认任务范围；
2. 正在读取资料；
3. 正在整理结构；
4. 正在生成并检查产物；
5. 已完成。

“查看技术详情”中再展示 Session、Goal、Profile、Skill、工具调用和失败分类。

## 9. 建议的第一期范围

第一期只做形成闭环所需的内容：

1. 任务导向首页；
2. 统一任务创建卡与教材版本确认卡；
3. 任务中心；
4. 数据来源中心只读状态页；
5. 四个助手模板；
6. 三个成熟场景包：教材课程树、学科知识点树、PDF/Word/图片整理；
7. 复用现有产物中心，并补充任务/场景标签。

第二期增加专项突破、多来源专题研究、备课资料包和定时教研动态。等至少两个
真实场景共同证明字段结构后，再抽象可编辑的“场景包管理”，不要先造通用画布。

## 10. 评审时重点确认

- 首页优先采用方案 A，还是要让角色助手占据首屏？
- 第一批置顶的三个场景是否就是：教材课程树、学科知识点树、文档整理？
- 任务是否需要跨 operator 与 mxb001～mxb004 汇总展示？
- 一线教师与管理员是否共用一个首页，还是管理员默认进入技术控制台？
- 专项突破是第一期加入，还是随第二期多来源场景一起发布？
